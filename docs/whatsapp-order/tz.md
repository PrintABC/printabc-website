## 1. Цель и контекст

### 1.1. Что строим

На странице калькулятора наклеек (`/stickers` на иврите, `/ru/stickers` на русском) клиент выбирает материал, форму, размер, количество и способ резки. Сервер считает цену. Сейчас под ценой стоит кнопка «להמשך: העלאת קובץ» / «Далее: загрузить макет» (`#calc-next`), которая никуда не ведёт (`href="#"`, `Pages/stickers.cshtml:115`).

Мы заменяем её **одной кнопкой «Заказать в WhatsApp»** («להזמנה ב-WhatsApp»). Кнопка — это ссылка вида `https://wa.me/972508494172?text=...`. Она открывает чат с PrintABC, а в поле ввода уже набран текст заказа: параметры и цена с НДС (точный шаблон — 6.1). Клиент сам отправляет сообщение и сам прикрепляет файл макета.

**wa.me** — официальный короткий адрес WhatsApp для открытия чата с номером. Параметр `text` задаёт текст, который будет набран в поле ввода (но не отправлен).

Цена в сообщении — **только для справки**: клиент может отредактировать текст до отправки, поэтому сотрудник перепроверяет цену сам, вводя параметры из сообщения в тот же калькулятор на сайте (Р6, 6.6).

### 1.2. Для кого

| Кто | Что получает |
|---|---|
| Клиент | Один понятный шаг: нажал кнопку, отправил сообщение, прикрепил файл. Не нужно заполнять форму с именем, телефоном и почтой. |
| Сотрудник PrintABC | Сообщение с параметрами и ценой в WhatsApp Business. Цену он перепроверяет в публичном калькуляторе сайта (6.6, 13.7). |
| Владелец | Сайт не хранит данные клиентов и файлы (Р1): меньше обязанностей по закону о защите приватности, нечему утечь. |

### 1.3. Границы

- Расчёт цены **не меняется** (Р15). Формулы и константы описаны в ТЗ v2 калькулятора. Мы только вызываем существующий метод `StickerCalculatorService.Calculate`; файл `StickerCalculatorService.cs` не меняется.
- Если ссылка на ТЗ v2 у вас не открывается, для этой задачи достаточно фактов ниже (сверены с кодом `Services/StickerCalculatorService.cs` и `Pages/stickers.cshtml`):

| Факт | Значение | Где в коде |

| Формы | круг (`Circle`), прямоугольник (`Rectangle`), фигурная (`Custom`) | `:8` |
| Резка | «на листе» (`Normal`, зазор 2 мм) или «поштучно» (`Separate`, зазор 5 мм, +20 ₪ без НДС) | `:9-13`, `:78`, `:114` |
| Минимальный заказ | 100 ₪ без НДС = 118 ₪ с НДС; меньшая сумма поднимается до минимума, `errorCode = "min"`, статус `Ready` | `:35-36`, `:118-122` |

| НДС | 18 % | `:37` |

- Мы не делаем загрузку файлов, онлайн-оплату, личный кабинет, базу заказов (раздел 3).

### 1.4. Итог работ одним списком

1. Кнопка «Заказать в WhatsApp» с текстом заказа по шаблону 6.1, запасная ссылка на почту и телефон.

```mermaid

## 3. Что не делаем и почему

| Не делаем | Почему | Как проверить, что не сделали |
|---|---|---|
| Загрузку файлов на сервер, форму с именем/телефоном/почтой (Р1) | Сайт без персональных данных: меньше обязанностей по поправке 13 к закону о защите приватности, нечему утечь, не нужен большой диск и антивирус на хостинге | `git grep -n -E "IFormFile|type=\"file\"|enctype=\"multipart"` по ветке пусто; на странице нет полей имени, телефона, почты |
| Web Share API и конвертацию картинок в PDF в браузере (Р3) | Утверждённый сценарий их заменил: файл клиент прикрепляет в чате сам | `git grep -n -E "navigator\.share|canShare|jsPDF|pdf-lib"` пусто |
| Хранение данных клиента, базу заказов | Цену сотрудник перепроверяет в калькуляторе (Р6), хранить нечего. Единственное, что остаётся на сервере, — технические логи App Service (раздел 9.1) | В проекте нет пакетов EF Core/ SQL, нет строк подключения в `appsettings*.json` |

#### 5.1.1. Регистрация опций

**Что.** Добавить класс опций `ContactOptions` (5.3) и проверку при старте.

```csharp
// Program.cs, внутри Main, сразу после builder.Services.AddLocalization(...)

#### 5.1.3. HSTS

```csharp
builder.Services.AddHsts(o =>
{
    o.MaxAge = TimeSpan.FromDays(365);
    o.IncludeSubDomains = false; // включить после ответа на ОВ-11
    o.Preload = false;
});
```

**Что.** Увеличить срок HSTS с 30 дней (по умолчанию) до 365. **Предложение** (срок).

**Почему.** **HSTS** (HTTP Strict Transport Security) — заголовок, который говорит браузеру: «на этот сайт ходи только по HTTPS столько-то дней». Без него первый запрос по `http://` можно перехватить и подменить страницу (и номер WhatsApp в ссылке). 30 дней — слишком короткий срок: браузер постоянного клиента «забывает» правило. 365 дней — распространённое значение. `IncludeSubDomains` не включаем, пока владелец не подтвердит, что все поддомены работают по HTTPS (иначе они станут недоступны).

**Как проверить.** На Azure: `curl -sI https://<домен>/stickers | grep -i strict-transport` → `max-age=31536000`. Локально заголовок не приходит: ASP.NET Core не шлёт HSTS для `localhost` — это нормально.

#### 5.1.4. Ограничение частоты запросов (rate limit)

**Что.** Встроенный `Microsoft.AspNetCore.RateLimiting` (пакет не нужен, входит в ASP.NET Core). Лимиты — **Предложение**:

| Что ограничиваем | Ключ | Лимит | Почему такой |
|---|---|---|---|
| `POST /stickers?handler=Calculate` (и `/ru/...`) | IP клиента | 60 запросов в минуту | Скрипт шлёт запрос не чаще раза в 300 мс и только после паузы в наборе. Живой клиент делает 5–20 запросов в минуту. 60 — запас для нескольких человек за одним IP (офис, мобильный оператор) |
| Остальное | — | без лимита | Статика и страницы не нагружают расчёт |

```csharp
// Program.cs, внутри Main, до builder.Build()
builder.Services.AddRateLimiter(o =>
{
    o.RejectionStatusCode = StatusCodes.Status429TooManyRequests;
    o.OnRejected = async (context, ct) =>
    {
        context.HttpContext.Response.Headers.RetryAfter = "60";
        await context.HttpContext.Response.WriteAsync("Too many requests", ct);
    };
    o.GlobalLimiter = PartitionedRateLimiter.Create<HttpContext, string>(ctx =>
    {
        string ip = ctx.Connection.RemoteIpAddress?.ToString() ?? "unknown";

        bool isCalculate = HttpMethods.IsPost(ctx.Request.Method)
            && string.Equals(ctx.Request.Query["handler"], "Calculate", StringComparison.OrdinalIgnoreCase);
        if (isCalculate)
            return RateLimitPartition.GetFixedWindowLimiter("calc:" + ip, _ => new FixedWindowRateLimiterOptions
            {
                PermitLimit = 60, Window = TimeSpan.FromMinutes(1), QueueLimit = 0
            });

        return RateLimitPartition.GetNoLimiter("none");
    });
});

// ...после app.Use(...заголовки...) и ДО app.UseRouting(), см. 5.1.6:
app.UseRateLimiter();
```

**Почему.**
- **Rate limit** — ограничение числа запросов от одного источника за отрезок времени. Без него кто угодно может засыпать сервер запросами расчёта (каждый — работа процессора).
- `GlobalLimiter` с условием, а не атрибут на странице: в Razor Pages атрибут нельзя повесить на один обработчик (`OnPostCalculate`), только на всю страницу. Условие по методу и `handler` явно и понятно.
- **Место в конвейере.** `GlobalLimiter` решает по методу и параметру `handler` — маршрутизация ему не нужна, поэтому `UseRateLimiter()` стоит **до** `UseRouting()`: лишний запрос отклоняется как можно раньше, до выполнения кода страницы.
- Ответ **429 Too Many Requests** — стандартный код «слишком много запросов». Браузер покажет понятный текст (5.8).
- **IP клиента.** `ctx.Connection.RemoteIpAddress` после `UseForwardedHeaders()` берётся из заголовка `X-Forwarded-For`. Сейчас `KnownProxies`/`KnownIPNetworks` очищены (`Program.cs:71-76`), то есть сервер верит этому заголовку от любого отправителя. На Azure App Service запрос всегда проходит через фронтенд Azure, который **дописывает** реальный IP в конец заголовка, а `ForwardLimit` по умолчанию = 1 берёт последнее значение. По нашим знаниям, это и есть реальный IP; на хостинге не проверено (ОВ-12). `ForwardLimit` **не менять**.

**Как проверить IP на тестовом сайте (ОВ-12).** Временно, только на тестовом сайте и **без коммита**, вставить в `Program.cs` сразу после `app.UseForwardedHeaders();`:

```csharp

{

В портале: App Service → Monitoring → **Log stream** (живой поток логов; работает, когда включено Application logging, 9.1) — найти строку `OV12`. Сравнить `ip=` с адресом, который показывает сайт whatismyip.com на том же телефоне. Совпадает — ОВ-12 закрыт. После проверки удалить вставку и выложить заново.

**Как проверить.**

#### 5.1.5. Заголовки безопасности и CSP

**Что.** Заменить закомментированный блок `Program.cs:93-104` на рабочий. Ставить **после** `UseHttpsRedirection()` и **до** `UseRouting()`, чтобы заголовки получали и страницы, и статические файлы.

```csharp
app.Use(async (ctx, next) =>
{
    var h = ctx.Response.Headers;
    h["X-Content-Type-Options"] = "nosniff";
    h["Referrer-Policy"] = "no-referrer";
    h["X-Frame-Options"] = "DENY";
    h["Permissions-Policy"] = "camera=(), microphone=(), geolocation=()";
    h["Content-Security-Policy"] =
        "default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; " +
        "font-src 'self'; connect-src 'self'; form-action 'self'; frame-ancestors 'none'; " +
        "base-uri 'self'; object-src 'none'; upgrade-insecure-requests";
    await next();
});
```

Подробные «почему» по каждому заголовку — в разделе 9.2. Коротко: **CSP** (Content Security Policy) — список источников, откуда браузеру разрешено грузить скрипты, стили, шрифты. `script-src 'self'` запрещает встроенные (`<script>` без `src`) и чужие скрипты. Если злоумышленник сумеет вставить скрипт в страницу, браузер его не выполнит — и скрипт не сможет подменить номер в ссылке `wa.me` на номер мошенника.

**Условие.** CSP включать **только после** выноса скрипта в файл (5.7–5.8) и переноса шрифтов (5.10). Иначе калькулятор и шрифты перестанут работать.

**Как проверить.**
- `curl -sI https://<домен>/stickers` показывает **все** заголовки из кода выше, каждый **с этим значением**: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`, `Content-Security-Policy: default-src 'self'; …` (строка целиком, как в коде) — и шестой, `Strict-Transport-Security: max-age=31536000` (его добавляет `UseHsts`, 5.1.3; только на хостинге, не на `localhost`). Полная команда — в 11.3. Другие заголовки в ответе (например, `Date`, `Server`, `Set-Cookie`, `x-ms-…` от Azure) допустимы: проверяется наличие и значение наших заголовков, а не отсутствие чужих.
- На страницах `/`, `/stickers`, `/ru/stickers` (и `/privacy`, если шаг 10 уже сделан; иначе — после шага 10) в консоли браузера (F12 → Console) **нет** ошибок `Refused to load` / `Content Security Policy`.
- Калькулятор считает, кнопка работает, шрифты Rubik/Assistant/Golos Text видны (F12 → Network → Font: файлы с нашего домена).

### 5.4. `Services/OrderMessageBuilder.cs` (новый)

**Что.** Сервис подставляет результат расчёта в шаблон сообщения (6.1): вычисляет значения переменных `{material}`, `{shape}`, `{size}`, `{quantity}`, `{cutMode}`, `{priceIncVat}`, собирает из ключей `.resx` текст и строит две ссылки: `wa.me` и `mailto:`. Он же решает, выдавать ли ссылки вообще (Р5).

**Предложение: где строить текст — вариант А (на сервере).**

| | Вариант А: сервер возвращает готовые `whatsappUrl`, `mailtoUrl` | Вариант Б: сервер возвращает цену, браузер собирает текст |
|---|---|---|
| Тексты | берутся из `.resx` как обычно | надо передать в браузер ~15 строк для каждого языка (JSON в странице) |
| Номер | из `ContactOptions`, только на сервере | номер тоже надо передать в браузер |
| Тесты | обычные модульные тесты C# | нужны тесты JS (в проекте нет инструментов для них) |
| Кодирование URL | одно место (`Uri.EscapeDataString`) | `encodeURIComponent` в браузере, отличается в мелочах |
| Подмена скриптом | ссылку целиком отдаёт сервер | скрипт собирает ссылку сам — подменённому скрипту проще |
| Размер ответа | +~2,5 КБ к JSON | меньше |

Выбран **вариант А**: всё, что влияет на текст, цену и номер, — в одном месте на сервере; браузер только подставляет готовую ссылку в `href`. Цена в тексте — та, что посчитал сервер (браузер на неё не влияет).

```csharp
// Services/OrderMessageBuilder.cs
using System.Globalization;
using Microsoft.Extensions.Localization;
using Microsoft.Extensions.Options;
using PrintABC.Data;
using PrintABC.Settings;
using static PrintABC.Services.StickerCalculatorService;
using static PrintABC.Utils.Helpers;

namespace PrintABC.Services;

/// <summary>
/// Значения переменных шаблона сообщения (6.1): уже переведённые и отформатированные строки.
/// Имена свойств = имена переменных: Material = {material}, PriceIncVat = {priceIncVat} и т. д.
/// </summary>
public sealed record OrderMessageValues(
    string Material, string Shape, string Size, string Quantity, string CutMode, string PriceIncVat);

public sealed class OrderMessageBuilder
{
    public const char Lrm = '\u200E'; // LEFT-TO-RIGHT MARK, раздел 7.3
    private readonly IStringLocalizer _l;
    private readonly ContactOptions _contact;

    public OrderMessageBuilder(IStringLocalizerFactory factory, IOptions<ContactOptions> contact)
    {
        // Те же ресурсы, что у страницы: Resources/Pages/stickers.{he,ru}.resx
        _l = factory.Create("Pages.stickers", typeof(OrderMessageBuilder).Assembly.GetName().Name!);
        _contact = contact.Value;
    }

    /// <summary>Окружить LRM: число со знаком ₪ и размер не «переедут» в иврите.</summary>
    public static string Ltr(string s) => Lrm + s + Lrm;

    /// <summary>Ссылки для кнопки. null — кнопка недоступна: ошибка ввода, ManualQuote, нет цены (Р5).</summary>
    public OrderLinks? TryBuild(QuoteRequest request, QuoteResponse quote)
    {
        if (quote.Status != ValidationStatus.Ready) return null;
        if (quote.PriceIncVatIls is not decimal price || price <= 0m) return null;
        return Build(request, price);
    }

    /// <summary>Переменные шаблона 6.1 из параметров заказа (QuoteRequest) и цены с НДС (QuoteResponse.PriceIncVatIls).</summary>
    public OrderMessageValues GetValues(QuoteRequest r, decimal priceIncVatIls)
    {
        var inv = CultureInfo.InvariantCulture;
        string size = r.Shape == ShapeType.Circle
            ? _l["msg_size_circle", Cm(r.DiameterMm)].Value
            : _l["msg_size_rect", Ltr(Cm(r.WidthMm) + "×" + Cm(r.HeightMm))].Value;

        return new OrderMessageValues(
            Material:    _l[MaterialKey(r.Material)].Value,
            Shape:       _l[ShapeKey(r.Shape)].Value,
            Size:        size,
            Quantity:    r.Quantity.ToString(inv),
            CutMode:     _l[r.CutMode == CutMode.Separate ? "cutting_separate" : "cutting_normal"].Value,
            PriceIncVat: Ltr(priceIncVatIls.ToString("0", inv) + " ₪"));
    }

    /// <summary>Текст сообщения: 7 строк шаблона 6.1, каждая — один ключ .resx.</summary>
    public string BuildText(QuoteRequest r, decimal priceIncVatIls, bool forEmail)
    {
        var v = GetValues(r, priceIncVatIls);
        string[] lines =
        [
            _l["msg_hello"].Value,
            _l["msg_material", v.Material].Value,
            _l["msg_shape", v.Shape, v.Size].Value,
            _l["msg_qty", v.Quantity].Value,
            _l["msg_cut", v.CutMode].Value,
            _l["msg_price", v.PriceIncVat].Value,
            (forEmail ? _l["msg_file_email"] : _l["msg_file_whatsapp"]).Value,
        ];
        // В WhatsApp перевод строки = \n (%0A). В письме по RFC 6068 = \r\n (%0D%0A).
        return string.Join(forEmail ? "\r\n" : "\n", lines);
    }

    public OrderLinks Build(QuoteRequest r, decimal priceIncVatIls)
    {
        string whatsapp = $"https://wa.me/{_contact.WhatsAppNumber}?text="
                          + Uri.EscapeDataString(BuildText(r, priceIncVatIls, forEmail: false));
        string mailto = $"mailto:{_contact.Email}"
                        + "?subject=" + Uri.EscapeDataString(_l["mail_subject"].Value)
                        + "&body=" + Uri.EscapeDataString(BuildText(r, priceIncVatIls, forEmail: true));
        return new OrderLinks(whatsapp, mailto);
    }

    private static string Cm(decimal mm) => (mm / 10m).ToString("0.#", CultureInfo.InvariantCulture);

    private static string MaterialKey(StickerMaterial m) => m switch
    {
        StickerMaterial.Paper => "paper",
        StickerMaterial.WhiteFilm => "whitefilm",
        StickerMaterial.TransparentFilm => "transparentfilm",
        _ => throw new ArgumentOutOfRangeException(nameof(m))
    };

    private static string ShapeKey(ShapeType s) => s switch
    {
        ShapeType.Circle => "shape_circle",
        ShapeType.Rectangle => "shape_rectangle",
        ShapeType.Custom => "shape_custom",
        _ => throw new ArgumentOutOfRangeException(nameof(s))
    };
}
```

**Почему (ключевые места).**
- **Переменные шаблона — отдельный record `OrderMessageValues`.** Связь «переменная шаблона → поле в коде» видна в одном месте (`GetValues`) и совпадает с таблицей 6.1. Тексты строк (`Материал:`, `Цена:` и т. д.) при этом остаются в `.resx`, а не в коде.
- Ключи материала, формы и резки — **те же**, что уже выводит страница (`stickers.cshtml:31, 48, 60`). Клиент видит в чате те же слова, что на сайте.
- Размер в тексте берётся из миллиметров `QuoteRequest` (то, что реально посчитал калькулятор после округления до 0,1 см, `stickers.cshtml.cs:67-78`), а не из того, что клиент набрал в поле. Так размер в тексте всегда соответствует цене.
- `IStringLocalizerFactory.Create("Pages.stickers", "PrintABC")` открывает тот же ресурс `PrintABC.Resources.Pages.stickers`, что и `IViewLocalizer` страницы. Язык берётся из `CultureInfo.CurrentUICulture` текущего запроса (его ставит `UseRequestLocalization`), поэтому singleton выдаёт he или ru правильно. **Проверить тестом U-01** — если базовое имя ресурса окажется другим, тест покажет ключ вместо текста.
- LRM вставляется **в коде**, а не в `.resx`: невидимые символы в `.resx` легко потерять при редактировании в Visual Studio. В коде он записан escape-последовательностью `'\u200E'`: так его видно в редакторе и нельзя потерять при копировании.
- `TryBuild` не выдаёт ссылки при `ManualQuote` и ошибках (Р5): возвращает `null`. Статус `Ready` с `ErrorCode = "min"` (цена поднята до минимального заказа 118 ₪) — **обычная** цена, ссылки выдаются.
- `Uri.EscapeDataString` кодирует пробел как `%20`, а не `+`. В параметре `text` знак `+` WhatsApp может показать буквально.

**Как проверить.** Тесты U-01…U-09 (11.1): точные тексты he/ru для T01 и «поштучно», длина ≤ 300 символов для самого длинного варианта, наличие `%0A`, `%E2%80%8E`, `%F0%9F%93%8E` в ссылке, `null` для `ManualQuote` и ошибки ввода.

**Почему (решение по элементу — Предложение).**

| | `<a href>` с настоящим адресом (выбрано) | `<button>` + `window.open` |
|---|---|---|
| Работает без JS | да: `OnGet` уже вставил ссылку | нет |
| Блокировка всплывающих окон | обычный переход по ссылке не блокируется | `window.open` после `await` блокируется браузерами |
| Встроенные браузеры Instagram/Facebook | обычная ссылка обрабатывается как переход (по знаниям, проверить) | поведение `window.open` непредсказуемо |
| Экранный диктор | «ссылка, Заказать в WhatsApp» — честно: это переход в другое приложение | «кнопка» |
| Долгое нажатие на телефоне | можно скопировать ссылку | нельзя |

- **Один элемент**, который меняет состояние, а не два (`#calc-next` + `#calc-next-off`): когда кнопка становится недоступной, фокус клавиатуры остаётся на ней же. При двух элементах скрытый элемент теряет фокус, и пользователь клавиатуры «выпадает» в начало страницы.
- Недоступная кнопка: убран `href` (ссылка без `href` никуда не ведёт), `aria-disabled="true"` (диктор говорит «недоступно»), `role="link"` и `tabindex="0"` (элемент остаётся в порядке Tab, чтобы пользователь диктора нашёл кнопку и услышал причину через `aria-describedby`). Атрибут `disabled` у `<a>` не существует.
- `target="_blank"`: на компьютере WhatsApp Web откроется в новой вкладке, калькулятор не пропадёт. `rel="noopener noreferrer"`: новая вкладка не получает доступ к нашей странице (`window.opener`) и не узнаёт адрес, с которого пришёл клиент.
- `#order-after` с `role="status"` пустой, текст вставляется при нажатии: так диктор надёжнее объявляет его (показ скрытого элемента объявляется не всеми дикторами).
- Видимый номер и `mailto:` рядом с кнопкой (Р12, «компьютер без WhatsApp»): на компьютере без WhatsApp `wa.me` открывает страницу WhatsApp с предложением установить приложение или открыть WhatsApp Web (по знаниям, проверить). Клиент без WhatsApp должен видеть другой способ заказать **без** нажатия на кнопку.
- Ссылка `/privacy` относительная: `LocalizedAnchorTagHelper` сам добавит `/ru` на русской странице.

**Как проверить.**
- В HTML ответа `GET /stickers` у `#order-wa` есть `href="https://wa.me/972508494172?text=..."`.
- С отключённым JavaScript (DevTools → Settings → Disable JavaScript) кнопка открывает чат с текстом для значений по умолчанию.
- Tab доходит до кнопки; при недоступной кнопке NVDA/VoiceOver/TalkBack читают «ссылка, недоступно» и причину.

decimal unitPriceIncVat = Math.Round(priceIncVatShown / request.Quantity, 4, MidpointRounding.AwayFromZero);
// в new StickerQuoteResponse { ... }:
UnitPriceIncVatIls = unitPriceIncVat,
```

При `ManualQuote` и ошибках поле, как и остальные суммы, клиенту не показывается. `UnitPriceExVatIls` в ответе можно оставить для тестов, но на странице и в скрипте он не используется. В `.resx` ключ `price_per_unit` поменять (5.12): «Цена за штуку с НДС» / «מחיר ליחידה כולל מע״מ».

Это только отображение, расчёт не меняется. «—» без готовой ссылки — по той же логике, что в скрипте: нет ссылки заказа — нет цены на экране.

### 5.8. `wwwroot/js/stickers-calc.js` (новый)

**Что.** Перенести логику встроенного скрипта и добавить управление кнопкой заказа.

```js
// wwwroot/js/stickers-calc.js
// Калькулятор наклеек и кнопка «Заказать в WhatsApp».
// Цена и ссылка приходят с сервера; этот файл сам ничего не считает.
(() => {
  'use strict';

  const form = document.getElementById('calc-form');
  if (!form) return;

  const totalOutput = document.getElementById('calc-total');
  // Р18: элемента calc-vat нет
  const unitOutput = document.getElementById('calc-unit');
  const shapeRadios = form.querySelectorAll('input[name="Shape"]');
  const sizeRound = document.getElementById('size-round');
  const sizeRect = document.getElementById('size-rect');
  const errorAlerts = form.querySelectorAll('.alert--error');
  const orderBtn = document.getElementById('order-wa');
  const orderReason = document.getElementById('order-wa-reason');
  const orderAfter = document.getElementById('order-after');
  const orderMail = document.getElementById('order-mail');
  const token = form.querySelector('input[name="__RequestVerificationToken"]').value;

  let controller = null;
  let requestId = 0;

  // ---------- вывод ----------
  function hideAllErrors() {
    errorAlerts.forEach(a => { a.hidden = true; });
  }

  function showError(code) {
    const block = form.querySelector(`[data-error="${CSS.escape(code)}"]`)
               || form.querySelector('[data-error="input"]');
    block.hidden = false;
  }

  function clearPrice() {
    totalOutput.textContent = '—';
    // Р18: строки НДС нет
    unitOutput.textContent = '—';
  }

  const money = n => Number(n).toFixed(0); // Р18: целые ₪

  // ---------- кнопка заказа ----------
  function enableOrder(order) {
    orderBtn.href = order.whatsappUrl;
    orderBtn.removeAttribute('aria-disabled');
    orderBtn.removeAttribute('role');
    orderBtn.removeAttribute('tabindex');
    orderBtn.classList.remove('is-disabled');
    orderBtn.classList.add('btn--primary');
    orderBtn.setAttribute('aria-describedby', 'order-wa-note');
    orderReason.hidden = true;
    orderMail.href = order.mailtoUrl;
  }

  // kind: 'busy' — идёт пересчёт; 'error' — цены нет
  function disableOrder(kind) {
    orderBtn.removeAttribute('href');
    orderBtn.setAttribute('role', 'link');
    orderBtn.setAttribute('aria-disabled', 'true');
    orderBtn.tabIndex = 0;
    orderBtn.classList.add('is-disabled');
    orderBtn.classList.remove('btn--primary');
    orderBtn.setAttribute('aria-describedby', 'order-wa-reason order-wa-note');
    orderReason.textContent = kind === 'busy' ? orderReason.dataset.textBusy : orderReason.dataset.textError;
    orderReason.hidden = false;
    orderMail.href = orderMail.dataset.plain; // письмо без старой цены
  }

  orderBtn.addEventListener('click', e => {
    if (orderBtn.getAttribute('aria-disabled') === 'true') {
      e.preventDefault();
      return;
    }
    // Р11: не «Заказ отправлен», а «проверьте, что сообщение ушло»
    orderAfter.textContent = orderAfter.dataset.text;
    // Р9: никакой аналитики и запросов на сервер здесь нет
  });

  // ---------- ответ сервера ----------
  function render(result) {
    hideAllErrors();
    const d = result.data;
    if (d.status === 'ready' && result.order) {
      totalOutput.textContent = money(d.priceIncVatIls) + '₪';
      // Р18: строки НДС нет, vatOutput удалён
      unitOutput.textContent = d.unitPriceIncVatIls; // Р17: с НДС
      enableOrder(result.order);
      return;
    }
    clearPrice();
    showError(d.status === 'manual_quote' ? 'price_max' : (d.errorCode || 'input'));
    disableOrder('error');
  }

  function fail(kind) { // 'network' | 'rate'
    hideAllErrors();
    clearPrice();
    showError(kind);
    disableOrder('error');
  }

  async function triggerCalculation() {
    controller?.abort();
    controller = new AbortController();
    const myId = ++requestId;
    disableOrder('busy');

    let response;
    try {
      response = await fetch('?handler=Calculate', {
        method: 'POST',
        headers: { 'RequestVerificationToken': token },
        body: new FormData(form),
        signal: controller.signal
      });
    } catch (err) {
      if (err.name === 'AbortError') return;   // отменён более новым запросом
      if (myId === requestId) fail('network');
      return;
    }
    if (myId !== requestId) return;            // устаревший ответ
    if (response.status === 429) { fail('rate'); return; }
    if (!response.ok) { fail('network'); return; }

    let result;
    try { result = await response.json(); } catch { fail('network'); return; }
    if (myId !== requestId) return;
    render(result);
  }

  // ---------- форма ----------
  function updateShapeUI(shape) {
    const round = shape === 'circle';
    sizeRound.hidden = !round;
    sizeRect.hidden = round;
  }

  function debounce(fn, wait) {
    let t;
    return (...args) => { clearTimeout(t); t = setTimeout(() => fn(...args), wait); };
  }
  const recalcLater = debounce(triggerCalculation, 300);

  shapeRadios.forEach(radio => radio.addEventListener('change', e => {
    if (e.target.checked) { updateShapeUI(e.target.dataset.shape); triggerCalculation(); }
  }));

  form.addEventListener('input', e => {
    orderAfter.textContent = '';            // подсказка относилась к прошлым параметрам
    if (e.target.name === 'Shape') return; // обработано в 'change'
    disableOrder('busy');                   // сразу, не через 300 мс
    recalcLater();
  });

  form.addEventListener('submit', e => e.preventDefault()); // Enter в поле не отправляет форму

  // Совпадают ли поля с тем, что прислал сервер в HTML (defaultValue / defaultChecked)?
  // Не совпадают, если браузер при возврате «Назад» восстановил введённые клиентом значения.
  function formIsAsRendered() {
    return [...form.elements].every(el =>
      el.type === 'radio' || el.type === 'checkbox' ? el.checked === el.defaultChecked
      : el.type === 'hidden' || !('defaultValue' in el) ? true
      : el.value === el.defaultValue);
  }

  const checkedShape = () => form.querySelector('input[name="Shape"]:checked')?.dataset.shape;
  updateShapeUI(checkedShape());
  // Цена и ссылка для значений по умолчанию уже пришли в HTML (OnGet, 5.6).
  // Пересчитываем при загрузке, только если поля отличаются от них — так кнопка не «мигает».
  if (!formIsAsRendered()) triggerCalculation();
  window.addEventListener('pageshow', e => {
    if (e.persisted) { updateShapeUI(checkedShape()); triggerCalculation(); }
  });
})();
```

**Почему (ключевые места).**

| Состояние | Кнопка | Что видит клиент | Почему |
|---|---|---|---|
| Цена готова (`status = ready`, есть `order`) | активна, `href` = `whatsappUrl` | цена, НДС, цена за штуку | можно заказывать |
| Идёт пересчёт (набор текста, ожидание ответа) | недоступна (`busy`) | «Пересчитываем цену…» | нельзя уйти в WhatsApp со старой ценой: кнопка блокируется **сразу** на `input`, а не через 300 мс |
| Ошибка ввода (`validation_error`) | недоступна | блок ошибки по `errorCode`, иначе общий `input`; «—» | в т. ч. `input`/`shape`, для которых раньше было `null₪` |
| Больше 1000 ₪ (`manual_quote`) | недоступна | блок `price_max` со ссылкой «напишите нам»; «—» | ссылки не выдаются (Р5) |
| Сбой сети или сервера (`!response.ok`, ошибка JSON, `fetch` упал) | недоступна | блок `network`; «—» | раньше оставалась старая цена |
| 429 | недоступна | блок `rate`; «—» | клиент понимает, что надо подождать |

- Решение по полю `status`, а не по наличию блока `[data-error]`: так `min` (минимальный заказ, статус `ready`) остаётся обычной ценой, а неизвестный код ошибки не превращается в «цену `null₪`».
- `requestId` отбрасывает «опоздавшие» ответы: если медленный старый ответ придёт после нового, он не перезапишет цену.
- `AbortError` не трогает экран: раньше отменённый запрос на миг ставил «—».
- В обработчике `click` нет `fetch`, `sendBeacon` и т. п. (Р9).
- **Нет пересчёта при загрузке**, если поля такие же, как в HTML. Старый скрипт всегда пересчитывал при загрузке; теперь сервер уже отдал цену и рабочую ссылку (5.6), и лишний запрос сделал бы кнопку на долю секунды недоступной («мигание»). Пересчёт при загрузке нужен только, когда браузер восстановил другие значения полей (возврат «Назад», автозаполнение) — это и проверяет `formIsAsRendered()`. При возврате из кэша «назад/вперёд» (`pageshow` с `persisted`) пересчитываем всегда: страница могла пролежать в памяти долго, а цены на сайте за это время могли обновиться — ссылка должна содержать текущую цену.
- **Задержка пересчёта не меняется** по сравнению со старым скриптом: количество, размеры, материал и резка — через 300 мс после последнего изменения (событие `input`, оно срабатывает и на радиокнопках), форма — сразу (`change`). Разница одна: при смене формы старый скрипт отправлял два запроса (сразу и через 300 мс), новый — один.
- Подсказка `#order-after` очищается при любом изменении параметров: она относится к уже отправленному сообщению.
- **`status = ready`, но `order = null`.** На практике этого не бывает: `Calculate` со статусом `Ready` всегда даёт цену не ниже минимума 118 ₪, а `TryBuild` возвращает `null` при `Ready` только для цены `null` или 0 (5.4). Если такое всё же придёт (ошибка на сервере), `render` покажет общий блок `input` и «—», кнопка недоступна. Это безопасно: уйти в WhatsApp без цены нельзя. Отдельный текст для этого случая не нужен.

**Как проверить.** Сценарии S-01…S-10 (раздел 11.4).

### 5.12. Ресурсы `Resources/Pages/stickers.he.resx` и `stickers.ru.resx`

Тексты для клиента — дословно. Тексты помечены **Предложение** (формулировки); юридически значимые строки (`order_note_privacy`, `order_fraud_note`) владелец показывает юристу.

**Как добавлять ключи.** Файлы `.resx` — это XML. Проще всего править их **вручную в текстовом редакторе** (в Visual Studio: правый клик по файлу → Open With → XML (Text) Editor). Каждый ключ — блок перед закрывающим `</root>`:

```xml
<data name="order_whatsapp" xml:space="preserve">

</data>
```

- Символы `<`, `>`, `&` внутри `<value>` пишутся как `&lt;`, `&gt;`, `&amp;`. Кавычки `"` и `«»` можно писать как есть.
- `{0}`, `{1}` — места подстановки для кода (`_l["msg_qty", 500]`).
- Файл сохранять в UTF-8 (так он сейчас и сохранён).

**Как создать новый `.resx`** (нужно для `Privacy.{he,ru}.resx`, `OrderTerms.{he,ru}.resx`, `Accessibility.{he,ru}.resx`). Самый надёжный способ: скопировать `Resources/Pages/stickers.he.resx` под новым именем и удалить в копии все блоки `<data …>…</data>`. | # | Ключ `.resx` | Текст ru в `.resx` | Что подставляется |
|---|---|---|---|

**Переменные: откуда берутся и как форматируются.** `r` — `QuoteRequest`, который `StickersModel.BuildQuoteRequest()` собрал из полей формы (`StickersModel.Material`, `Shape`, `DiameterCm`, `WidthCm`, `HeightCm`, `Quantity`, `CutMode`; размеры уже переведены в мм). `quote` — `QuoteResponse`, который вернул `StickerCalculatorService.Calculate(r)`. | Переменная | Свойство `OrderMessageValues` | Источник в коде | Перевод (ключ `.resx`) | Формат | Пример T01 ru | Пример T01 he |
|---|---|---|---|---|---|---|
| `{material}` | `Material` | `r.Material` (= `StickersModel.Material`) | `Paper` → `paper`, `WhiteFilm` → `whitefilm`, `TransparentFilm` → `transparentfilm` | текст ключа как есть (с заглавной буквы, как на сайте) | Самоклеящаяся бумага | נייר מדבקה |
| `{shape}` | `Shape` | `r.Shape` (= `StickersModel.Shape`) | `Circle` → `shape_circle`, `Rectangle` → `shape_rectangle`, `Custom` → `shape_custom` | текст ключа как есть | Круглая | עגולה |
| `{size}` | `Size` | круг: `r.DiameterMm`; прямоугольник и фигурная: `r.WidthMm`, `r.HeightMm` (из `StickersModel.DiameterCm` / `WidthCm` / `HeightCm`, округлённых до 0,1 см) | круг: `msg_size_circle` («диаметр {0} см»); иначе `msg_size_rect` («{0} см») | сантиметры = мм / 10, формат `0.#`, точка (`5`, `4.5`); для прямоугольника `ширина×высота` со знаком `×` (U+00D7), окружённое LRM: `[LRM]5×3[LRM]` | диаметр 5 см | קוטר 5 ס״מ |
| `{quantity}` | `Quantity` | `r.Quantity` (= `StickersModel.Quantity`) | — | целое число, без разделителей тысяч, `InvariantCulture` (`1000000`, не `1 000 000`) | 500 | 500 |
| `{cutMode}` | `CutMode` | `r.CutMode` (= `StickersModel.CutMode`) | `Normal` → `cutting_normal`, `Separate` → `cutting_separate` | текст ключа как есть | На листе (надсечка) | על גיליון (חיתוך חלקי) |
| `{priceIncVat}` | `PriceIncVat` | `quote.PriceIncVatIls` (`decimal?`; ссылки строятся только при `quote.Status == Ready` и цене > 0, Р5) | — | целое число без дробной части (`"0"`, `InvariantCulture`, Р18), пробел, `₪`; целиком окружено LRM: `[LRM]284 ₪[LRM]` | [LRM]284 ₪[LRM] | [LRM]284 ₪[LRM] |

`[LRM]` — невидимый символ U+200E (раздел 7.3). Его вставляет код (`OrderMessageBuilder.Ltr`), в `.resx` его нет.

Правила:
- Размер в сантиметрах, как на сайте. Значения — те, что посчитал калькулятор (после округления до 0,1 см в `BuildQuoteRequest`), а не то, что клиент набрал в поле.
- Цена — **цена с НДС** из ответа сервера (`QuoteResponse.PriceIncVatIls`). НДС отдельно и цена за штуку в текст не входят.
- Даты, кода заказа и версии прайса в тексте **нет** (решение владельца от 22.10.2026).
- Данных клиента в тексте нет.

**Почему так.**
- Каждая строка с подписью («Материал:», «Форма:»): сотрудник быстро переносит значения в калькулятор на сайте (6.6), а текст остаётся понятным в чате. Значения берутся из тех же ключей, что подписи на сайте, поэтому совпадают слово в слово (с заглавной буквы, как на сайте).
- Просьба про «Документ», а не «Галерея» (Р4): при отправке через «Галерею» WhatsApp пережимает картинку (по знаниям: до ~1600–2560 px по длинной стороне, без прозрачности) — для печати не годится. Через «Документ» файл приходит без изменений.
- Длина до ~300 символов (Р4): короткий текст надёжнее проходит через URL и читается в чате.

**Как проверить.** Тесты U-02…U-05 сравнивают текст с примерами 6.2 **посимвольно**. Тест U-06 проверяет длину самого длинного варианта.

### 6.3. Подсчёт символов

Считаем длину строки C# (`string.Length`) вместе с переводами строк. `Length` считает **единицы UTF-16**: почти каждый символ — 1 единица, а 📎 (U+1F4CE, вне основной плоскости Unicode) — **2** единицы. LRM — 1 единица. Для сравнения дано и число **кодовых точек** (символов Unicode, где 📎 = 1) — так считает, например, `len()` в Python.

| Пример | Кодовых точек без LRM | LRM | Кодовых точек всего | **`Length` (UTF-16)** | Байт UTF-8 |
|---|---|---|---|---|---|
| T01, he | 192 | 2 | 194 | **195** | 331 |
| T01, ru | 230 | 2 | 232 | **233** | 413 |
| Поштучно, he | 182 | 4 | 186 | **187** | 320 |
| Поштучно, ru | 218 | 4 | 222 | **223** | 398 |

Самый длинный возможный текст получается при: круге с диаметром 31 (максимум поля, 4.3) или прямоугольнике/фигурной `31×45.8`, количестве `1000000` (максимум `[Range]` в `StickersModel`), цене `999.99`. Перебор всех 18 сочетаний материала × формы × резки даёт максимум **`Length` = 243** (русский: «Самоклеящаяся бумага», «Прямоугольная», «На листе (надсечка)») и **209** (иврит). Тест U-06 повторяет этот перебор на C# и проверяет `Length ≤ 300` на обоих языках. Если тест не проходит — сокращать `msg_file_whatsapp`, а не убирать параметры.

### 6.4. Итоговая ссылка WhatsApp

Как строится: `https://wa.me/` + номер из `Contact:WhatsAppNumber` + `?text=` + `Uri.EscapeDataString(текст)`.

Что кодируется и как (**URL-кодирование** — замена символов, которые нельзя писать в адресе, на `%` и шестнадцатеричные байты UTF-8):

| Символ | В ссылке |
|---|---|
| перевод строки `\n` | `%0A` |
| пробел | `%20` (не `+`) |
| LRM U+200E | `%E2%80%8E` |
| 📎 U+1F4CE | `%F0%9F%93%8E` |
| `₪` U+20AA | `%E2%82%AA` |
| `×` U+00D7 | `%C3%97` |
| `→` / `←` | `%E2%86%92` / `%E2%86%90` |
| `:` `,` `!` `(` `)` `"` | `%3A` `%2C` `%21` `%28` `%29` `%22` |
| `-` `.` | без изменений |

### 6.6. Цена в сообщении — только для справки

**Что.**
- Цена в тексте сообщения — **справочная**: это цена, которую калькулятор показал клиенту в момент нажатия кнопки. Подтверждением заказа она не является.
- Сотрудник **перепроверяет** цену сам: открывает публичный калькулятор сайта (`/stickers` или `/ru/stickers`), вводит параметры из сообщения (материал, форма, размер, количество, нарезка) и сравнивает цену с НДС на экране с ценой в сообщении. Порядок действий — 13.7.
- Совпала — подтверждение (13.4) по этой цене. Не совпала — сотрудник пишет клиенту цену из калькулятора, подтверждение — после согласия клиента.
- Код на сайте для этого не нужен: калькулятор уже есть, а одинаковые параметры дают одинаковую цену (4.3).

**Почему.**
- Владелец отказался от кода заказа и проверки подлинности сообщения (решение от 22.10.2026). Без кода сайт не может доказать, что клиент не изменил текст до отправки (в поле ввода WhatsApp его можно отредактировать), поэтому цене из текста **нельзя доверять** как окончательной.
- Пересчёт в том же публичном калькуляторе даёт ту же цену, что видел клиент, — пока не изменились цены на сайте. Если цены изменились между расчётом клиента и проверкой, сотрудник увидит новую цену и согласует её с клиентом.
- Не нужны секретный ключ, служебная страница с паролем, её защита и тесты.

**Как проверить.** Ручная проверка S-11 (11.4): цена, полученная по параметрам из текста сообщения, совпадает с ценой в сообщении. Шаблон автоответа и подтверждения (13.3, 13.4) не обещают клиенту цену из его сообщения до перепроверки.

## 7. Локализация и RTL

### 7.1. Ключи

Все тексты кнопки, подсказок, ошибок и сообщения — в `Resources/Pages/stickers.{he,ru}.resx` (5.12). Язык сообщения = язык страницы (`/stickers` → иврит, `/ru/stickers` → русский): его определяет `UrlPathCultureProvider`.

### 7.2. Как выглядит текст в чате на иврите

**RTL** (right-to-left) — письмо справа налево. Иврит пишется справа налево, а цифры и латиница внутри него — слева направо. Браузер и WhatsApp расставляют такие куски по **алгоритму двунаправленного текста Unicode** (bidi). Направление строки определяется **первой «сильной» буквой**: ивритская буква → строка справа налево.

Ожидаемый вид в пузыре WhatsApp (выравнивание по правому краю):

```text
                         שלום! אני רוצה להזמין מדבקות.
                                       חומר: נייר מדבקה
                                 צורה: עגולה, קוטר 5 ס״מ
                                           כמות: 500 יח׳
                          חיתוך: על גיליון (חיתוך חלקי)
                              מחיר: 284 ₪ כולל מע״מ
     את קובץ ההדפסה אשלח מיד דרך 📎 ← "מסמך" (לא "גלריה").
```

### 7.3. LRM: где и зачем

**LRM** (U+200E, LEFT-TO-RIGHT MARK) — невидимый символ «здесь направление слева направо». Он ничего не показывает, но подсказывает bidi-алгоритму, к чему относятся соседние нейтральные символы (пробел, `-`, `×`, `₪`).

Без LRM типичные ошибки (Р8):
- `5×3` в ивритской строке может показаться как `3×5`: знак `×` «нейтральный», и между двумя числами в RTL-строке алгоритм может развернуть порядок;
- `₪` и число меняются местами или `₪` «уезжает» к соседнему ивритскому слову.

Где стоят LRM (с обеих сторон куска):

| Кусок | Как в строке |
|---|---|
| Цена со знаком валюты | `[LRM]284 ₪[LRM]` |
| Размер прямоугольника | `[LRM]5×3[LRM]` |

Правила:
- **Никогда не начинать ивритскую строку с LRM**: тогда первым «сильным» символом станет LRM, и вся строка развернётся слева направо. Поэтому в каждой строке сначала идёт ивритская подпись («מחיר:», «צורה:»).
- LRM вставляет **код** (`OrderMessageBuilder.Ltr`), не `.resx`.
- В русском тексте LRM ничего не меняет, но стоит там же — один код для обоих языков.
- На сайте (HTML) для таких кусков уже используются `<span class="ltr">` и `<bdi dir="ltr">` — LRM в HTML не нужен.

### 7.4. Числа и валюта

| Что | Формат (he и ru) | Почему |
|---|---|---|
| Цена | `284 ₪`, целое (Р18), `₪` после числа через пробел | В Израиле десятичный разделитель — точка; один формат на обоих языках: сотрудник сравнивает цену из сообщения с ценой калькулятора (он тоже выводит точку, 5.7.4) без перевода формата. **Предложение** (для ru можно было бы запятую, но тогда цена в сообщении и на сайте выглядела бы по-разному) |
| Количество | `500`, без разделителей тысяч | Разделители (`1,000` / `1 000`) различаются по языкам и путаются с дробями |
| Размер | `5`, `4.5`, `5×3` | Как вводит клиент на сайте |

### 7.5. Проверка на реальном WhatsApp

Обязательные ручные проверки — M-06 (раздел 11.5): на Android, iPhone и WhatsApp Web открыть ссылки T01 he и «поштучно» he и сверить с 7.2: цена `284 ₪` целиком, `5×3` (не `3×5`), строки выровнены вправо. Сделать скриншоты и приложить к PR.

**Как проверить весь раздел.** Тесты U-02…U-05 (точный текст с LRM в нужных местах) + M-06.

## 8. Доступность

**IS 5568** — израильский стандарт доступности сайтов, основан на рекомендациях WCAG (уровень AA). Обязателен для сайтов бизнеса по правилам о равных правах людей с инвалидностью (порог оборота уточняется, ОВ-3). Требования Р10:

| # | Что | Почему | Как проверить |
|---|---|---|---|
| A-1 | Кнопка — элемент `<a>` с текстом «Заказать в WhatsApp» / «להזמנה ב-WhatsApp» (видимый текст = доступное имя) | Диктор читает понятную подпись; голосовое управление («нажми Заказать в WhatsApp») работает, когда имя совпадает с видимым текстом | NVDA (Windows) / VoiceOver (iPhone) / TalkBack (Android): «ссылка, Заказать в WhatsApp» |
| A-2 | Доступна с клавиатуры: Tab доходит, Enter открывает | Не все пользуются мышью | Только клавиатура: Tab → кнопка, видна рамка фокуса, Enter → чат |
| A-3 | Видимый фокус (5.9) | Пользователь клавиатуры должен видеть, где он | Рамка фокуса видна в двух режимах: обычном и в режиме высокого контраста панели доступности (`html.a11y-contrast`, 5.9). Тёмной темы на сайте нет |
| A-4 | Состояние «недоступно» видимое (серый вид, текст причины) и программное (`aria-disabled="true"`) | Р10. Цвет сам по себе не передаёт состояние | Диктор: «ссылка, недоступно» + причина (`aria-describedby`); Enter на недоступной кнопке ничего не делает |
| A-5 | Фокус не теряется при смене состояния (один элемент, 5.7.1) | Иначе пользователь клавиатуры «выпадает» в начало страницы | Фокус на кнопке, изменить количество с клавиатуры, вернуться Shift+Tab — фокус на месте |

## 9. Безопасность и приватность

### 9.1. Что сайт хранит

| Что | Где | Срок | Есть ли данные клиента |
|---|---|---|---|
| Ничего о заказах | — | — | нет: ни базы, ни файлов, ни форм (Р1) |
| Логи App Service: журнал веб-сервера (IP, адрес страницы, браузер, время) и журнал приложения | Azure, файловая система App Service | **1–7 дней**; **Предложение:** 3 дня | IP-адрес — технические данные; текст заказа в логи не попадает (он в адресе `wa.me`, на который уходит браузер клиента, а не наш сервер) |
| Cookie защиты от подделки запросов (`.AspNetCore.Antiforgery.*`) | браузер клиента | до закрытия браузера | нет, технически необходимая |
| Настройки панели доступности (`localStorage`, ключ `printabc-a11y`, `main.js:41`) | браузер клиента | пока клиент не очистит | нет, только на устройстве |

**Что.** В Azure: App Service → Monitoring → App Service logs. Набор полей зависит от ОС App Service (ОВ-21). Ниже — по знаниям, в портале не проверено:
- **Linux** (проект собирается в Linux-контейнер: `PrintABC.csproj:8` `DockerDefaultTargetOS=Linux`, `Dockerfile:4`): включить **Application logging (File System)**, **Retention Period (Days) = 3**, Quota (MB) — по умолчанию. Отдельного пункта «Web server logging» у Linux App Service нет.
- **Windows** (если App Service окажется на Windows): **Application logging (Filesystem)** и **Web server logging (File System)**, у обоих **Retention Period (Days) = 3**.

Если названия в портале другие — найти поле срока хранения (Retention) и поставить 3, а реальные названия записать в PR.

**Почему.** Логи нужны, чтобы разбираться со сбоями. Хранить их дольше недели незачем, а IP-адреса — персональные данные в широком смысле: чем короче срок, тем меньше риск. Срок 1–7 дней утверждён владельцем (см. «Как читать этот документ»), 3 дня — середина.

**Как проверить.** Скриншот настройки в портале Azure приложить к PR / в журнал работ. Через 4 дня открыть **Kudu** (консоль администрирования App Service: `https://<app>.scm.azurewebsites.net`) и убедиться, что нет файлов логов старше 3 дней. Linux: Kudu → **SSH** (или Bash) → `ls -la /home/LogFiles`. Windows: Kudu → **Debug console** → CMD → папка `LogFiles`.

### 9.2. Заголовки и CSP

Код — в 5.1.5. Зачем каждый:

| Заголовок | Значение | Почему |
|---|---|---|
| `Content-Security-Policy` | `default-src 'self'` — по умолчанию только свой домен | Ничего чужого без явного разрешения |
| | `script-src 'self'` (без `'unsafe-inline'`) | Встроенный или чужой скрипт не выполнится — не сможет подменить номер в ссылке на номер мошенника |
| | `style-src 'self'`, `font-src 'self'` | После переноса шрифтов (5.10) Google не нужен |
| | `img-src 'self' data:` | Иконки и картинки сайта; `data:` — для встроенных SVG в CSS, если есть (было в старом CSP) |
| | `connect-src 'self'` | `fetch` только на свой сервер (`?handler=Calculate`) |
| | `form-action 'self'` | Формы отправляются только на свой сервер |
| | `frame-ancestors 'none'` | Сайт нельзя встроить в чужую страницу (защита от «кликджекинга» — подложенной поверх невидимой кнопки) |
| | `object-src 'none'` | Запрет плагинов (`<object>`, `<embed>`) |
| | `base-uri 'self'` | Нельзя подменить `<base href>` и перенаправить относительные ссылки |
| | `upgrade-insecure-requests` | Если где-то осталась ссылка `http://`, браузер возьмёт `https://` |
| `X-Content-Type-Options` | `nosniff` | Браузер не «угадывает» тип файла: текст не исполнится как скрипт |
| `Referrer-Policy` | `no-referrer` — **Предложение** | Переход в WhatsApp и на другие сайты не сообщает адрес нашей страницы. Нам заголовок `Referer` нигде не нужен (защита форм работает через токен). Вариант `strict-origin-when-cross-origin` сообщал бы чужим сайтам домен — без пользы для нас |
| `X-Frame-Options` | `DENY` | То же, что `frame-ancestors`, для старых браузеров |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` — **Предложение** | Сайту не нужны камера, микрофон, геолокация; запрет на случай внедрённого кода |
| `Strict-Transport-Security` | `max-age=31536000` | 5.1.3 |

**Ссылки `wa.me` и `mailto:` CSP не ограничивает**: CSP управляет загрузкой ресурсов и отправкой форм, а не переходом по ссылке. Кнопка заказа продолжит работать.

**Как проверить.** 11.3: `curl -I`, securityheaders.com (оценка не ниже **A**), консоль браузера без ошибок CSP.

### 13.7. Порядок проверки заказа сотрудником

Цена в сообщении клиента — **только для справки** (Р6, 6.6): клиент мог изменить текст до отправки. Поэтому цену сотрудник всегда перепроверяет сам, на том же калькуляторе, которым пользовался клиент. Пароль и служебная страница не нужны.

1. Открыть на сайте калькулятор: `/stickers` (иврит) или `/ru/stickers` (русский) — на любом устройстве, как обычный посетитель.
2. Выставить параметры **из сообщения**: материал (строка «Материал» / «חומר»), форму и размер («Форма» / «צורה»: для круга — диаметр, для прямоугольной и фигурной — ширина × высота), количество, нарезку.
3. Сравнить «Цена с НДС» на экране с ценой в строке «Цена» / «מחיר» сообщения.
4. Совпало → подтверждение 13.4 с этой ценой. Не совпало (клиент изменил текст, или цены на сайте обновились после его расчёта) или вместо цены «—» с сообщением о цене выше 1000 ₪ (блок `price_max`) → написать клиенту цену из калькулятора, подтверждение — после его согласия.
5. Дождаться файла «Документом»; если пришёл через «Галерею» — попросить прислать «Документом».

Эти действия легко забыть, потому что они случаются редко. Владелец заносит их в свой календарь в тот день, когда происходит событие из первого столбца.

| `using static X;` | Подключает **члены** класса `X` (вложенные типы, константы): можно писать `StickerMaterial.Paper` вместо `StickerCalculatorService.StickerMaterial.Paper` | `using static PrintABC.Services.StickerCalculatorService;` |

| `?.` и `??` | `a?.B` — «`B`, если `a` не `null`, иначе `null`»; `a ?? b` — «`a`, а если `null`, то `b`» | `Model.Order?.MailtoUrl ?? Contact.Value.MailtoLink` |

| `$"...{x}..."` | Интерполированная строка: `{x}` заменяется значением | `$"https://wa.me/{WhatsAppNumber}"` |
| `1_000_000` | Подчёркивания в числе — только для читаемости | `[Range(1, 1_000_000)]` |
| `sealed` | От класса нельзя наследовать. На работу не влияет; ставится, когда наследование не задумано | `public sealed class OrderMessageBuilder` |
| Именованные аргументы | При вызове метода или конструктора можно указать имя параметра перед значением: `Имя: значение`. Так видно, какое значение куда идёт | `new OrderMessageValues(Material: ..., PriceIncVat: ...)` в `GetValues` (5.4) |

## 1. Итог в целых шекелях, без строки НДС — `10-whole-shekels.diff`

**Решение владельца.** Итог с НДС показывать в целых шекелях, к ближайшему (.50 вверх): 1346.19 → «1346 ₪». Цена за штуку = этот целый итог ÷ тираж, 2 знака (1346 / 100 = 13.46 ₪). Строку «в т. ч. НДС» не показывать нигде: ни на странице, ни в нижней панели, ни в WhatsApp.

**Где.**
- `Services/CatalogCalculatorService.cs:148-150` — расчёт НДС и цены за штуку; `:152-162` — ответ.
- `Data/CatalogQuoteResponse.cs:11` — поля ответа.
- `Pages/Catalogs.cshtml:310-313` — строка «в т. ч. НДС»; `:441` `vatOutput`; `:450-455` `money()`; `:606-608`, `:616-618`, `:626-629` — вывод цены.
- `Pages/Catalogs.cshtml.cs:118-121` — цена в сообщении WhatsApp.
- `Resources/Pages/Catalogs.{he,ru}.resx` — ключ `price_just_vat` больше не нужен, удалён (у наклеек свой resx, их это не касается).

**Код.** Округляем **на сервере** — страница только показывает число:

```csharp
// было
decimal priceIncVat = priceExVat + vat;
decimal pricePerCopy = Math.Round(priceIncVat / req.Quantity, 2, MidpointRounding.AwayFromZero);

// стало
decimal priceIncVat = priceExVat + vat;
//the client sees the total incl. VAT in whole shekels, to the nearest (.50 up): 1346.19 -> 1346
decimal totalIncVat = Math.Round(priceIncVat, 0, MidpointRounding.AwayFromZero);
//price per copy = the rounded total / quantity, with agorot: 1346 / 100 = 13.46
decimal pricePerCopy = Math.Round(totalIncVat / req.Quantity, 2, MidpointRounding.AwayFromZero);
...
TotalIncVatIls = totalIncVat,   // новое поле ответа (в JSON: totalIncVatIls)
```

`PriceIncVatIls` (1346.19) и `VatIls` остаются в ответе для тестов и для своих нужд, но страница их больше не показывает.

На странице удалён блок `<div class="price-box__row">…price_just_vat…calc-vat…</div>` и все строки `vatOutput…`. Формат цены:

```js
function money(value, decimals = 2) {
    return lrm + Number(value).toFixed(decimals) + ' ₪' + lrm;
}
...
totalOutput.textContent = money(result.data.totalIncVatIls, 0); //"1346 ₪"
unitOutput.textContent = money(result.data.unitPriceIncVatIls);  //"13.46 ₪"
```

Нижняя панель на телефоне копирует текст из `#calc-total`, поэтому там тоже «1346 ₪» без доработки. В сообщении WhatsApp:

```csharp
string price = response.TotalIncVatIls?.ToString("0", CultureInfo.InvariantCulture) ?? "";  // было PriceIncVatIls "0.00"
```

**Почему `Math.Round(…, MidpointRounding.AwayFromZero)`:** без второго параметра C# округляет .5 «к чётному» (2.5 → 2), а владелец решил «.50 вверх».

**Как проверить.** Открыть `/ru/catalogs` по умолчанию (A4, скоба, 12 стр. 130 г, обложка 250 4+4, 100 шт.): «Итого с НДС 1346 ₪», «Цена за экземпляр 13.46 ₪», строки НДС нет. На телефоне внизу «Итого 1346 ₪». Кнопка WhatsApp: «Цена: 1346 ₪ с НДС». В DevTools → Network → `?handler=Calculate` → в ответе `"totalIncVatIls":1346`.

## 3. Автосмена числа страниц с пояснением — `12-auto-change-pages.diff`

**Решение владельца.** Если после смены бумаги, переплёта или обложки число страниц не помещается в лимит, калькулятор сам ставит допустимое число и пишет под полем, что и почему: «Для 250 г со скобой максимум 12 стр. — исправили 32 → 12.» Цена пересчитывается сразу.

**Проблема в коде.** `Pages/Catalogs.cshtml:546-552` (`updatePageLimits`) уже двигает значение к допустимому, но молча — клиент не замечает, что заказ стал другим.

**Где.** `Pages/Catalogs.cshtml:125` (после подсказки под полем — новая строка), `:522-555` (`updatePageLimits`), `:713` (вызов при загрузке); `wwwroot/css/pages.css` (в конец); resx: `autofix_max`, `autofix_min`, `autofix_step`, `binding_with_staple`, `binding_with_spiral`.

**Код.** Под подсказкой поля — пустая строка для пояснения, тексты приходят из resx через `data-*`:

```html
<p class="field__hint cat-autofix" data-autofix="" role="status" hidden=""
   data-text-max="@L.GetString("autofix_max")" data-text-min="@L.GetString("autofix_min")" data-text-step="@L.GetString("autofix_step")"
   data-text-staple="@L["binding_with_staple"]" data-text-spiral="@L["binding_with_spiral"]"></p>
```

В скрипте запоминаем старое число и, если оно поменялось, показываем текст:

```js
function updatePageLimits(silent = false) {      // silent = при загрузке страницы ничего не пишем
    ...
    const oldPages = parseInt(pagesInput.value);
    let pages = oldPages || limits.min;
    ... // как было: вниз к max, вверх к min, к кратному шагу
    pagesInput.value = pages;
    if (!silent && !isNaN(oldPages) && oldPages != pages)
        showAutofix(oldPages > limits.max ? 'max' : oldPages < limits.min ? 'min' : 'step', limits, oldPages, pages);

    ...
}
pagesInput.addEventListener('input', () => autofix.hidden = true); // клиент сам меняет число — старое пояснение убираем
```

`showAutofix()` подставляет в шаблон бумагу (текст выбранной кнопки, «250 г»), переплёт в нужной форме («скобой» / «спиралью»), лимит, старое и новое число. Цену отдельно пересчитывать не нужно: клик по кнопке уже вызвал событие `input` формы, а запрос уходит через 300 мс, когда число страниц уже исправлено.

Тексты:

## 5. «Назад» восстанавливает выбор — `14-back-restore.diff`

**Решение владельца.** После «Назад» в браузере форма должна вернуть выбор клиента (формат, переплёт, страницы, бумага, обложка, печать обложки, ламинация, тираж) и пересчитать цену.

**Проблема.** У формы `autocomplete="off"`, поэтому браузер при возврате (если страница не из кэша) сбрасывает форму на значения по умолчанию, а клиент думает, что цена посчитана для его заказа.

**Где.** `Pages/Catalogs.cshtml:713-718` (конец скрипта: первый расчёт и `pageshow`).

**Код.** Выбор пишем в `sessionStorage` (живёт только в этой вкладке, пока она открыта) при каждом изменении и читаем при загрузке:

```js
const STATE_KEY = 'printabc-catalogs-calc';
const STATE_FIELDS = ['Format', 'Binding', 'InnerPageCount', 'InnerPaper', 'HasCover', 'CoverPaper', 'CoverPrint', 'Lamination', 'Quantity'];
function saveState() { ... try { sessionStorage.setItem(STATE_KEY, JSON.stringify(state)); } catch (e) { } }
function restoreState() { ... try { state = JSON.parse(sessionStorage.getItem(STATE_KEY)); } catch (e) { state = null; } ... }
form.addEventListener('input', saveState);
form.addEventListener('change', saveState);

function init() {
    restoreState();
    updatePageLimits(true); // проверяет восстановленные значения по лимитам, без пояснения
    updateUIElements();
    triggerCalculation();
}
init();
window.addEventListener('pageshow', e => { if (e.persisted) init(); });  // страница вернулась из кэша браузера
```

Пояснения:
- Все обращения к `sessionStorage` в `try/catch`: в приватном режиме или при запрете сайтов хранилище бросает ошибку — страница должна работать, просто без памяти (проверено: подменили `sessionStorage` на бросающий ошибку, цена считается, ошибок в консоли нет).
- Значение, которого нет в списке (например, кто-то руками записал `Format: "A3"`), пропускается: остаётся значение по умолчанию.
- `saveState` подписан **после** обработчика смены бумаги/переплёта, поэтому сохраняется уже исправленное число страниц.
- Почему `init()` и при загрузке, и на `pageshow` с `persisted`: обычный возврат — это новая загрузка страницы, там срабатывает `init()` сразу; возврат из кэша браузера (bfcache) скрипт заново не запускает, только событие `pageshow` с `persisted = true`. Так покрыты оба случая и нет двойного запроса при обычной загрузке.

**Как проверить** (проверено, he и ru, телефон и ПК): выбрать A5, скоба, 80 г, 16 стр., обложка 300 г 4+0, глянцевая ламинация, тираж 250 → итог 2272 ₪. Перейти на главную, нажать «Назад» → всё выбрано как было, «Ваш заказ» и итог 2272 ₪. Обновить страницу (F5) — тоже восстанавливается. Новая вкладка — значения по умолчанию.

## 6. Сообщение WhatsApp — `15-whatsapp-message.diff`

**Решение владельца.** Строка блока с названием бумаги: «12 стр., мелованная матовая 130 г» / «12 עמ׳, כרומו מט 130 גרם» (80 г = офсет / אופסט). Цена целыми (сделано в п. 1). Строка про файл одной строкой.

**Где.** `Pages/Catalogs.cshtml.cs:95` (строка блока), `:107` (строка обложки), конец класса — новый метод; resx `msg_file_whatsapp` (в нём лишний перенос `%0a`), новые `msg_paper_80`, `msg_paper_coated`.

**Код.**

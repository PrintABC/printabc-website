## Б2. Сломанная ссылка WhatsApp

**Было.** В resx шаблон с ручными `%0a` и `%0📎`. `%0` без второй цифры — сломанный код, браузер не может прочитать
ссылку. Нет строки «Начальный номер», конец сообщения обрезан.

**Стало.** В resx обычный текст, каждая строка сообщения своим ключом (`msg_hello`, `msg_kind`, … `msg_file`),
в `{0}` подставляется значение. Скрипт соединяет строки через `'\n'` и кодирует всё одним `encodeURIComponent`:

```js
const msg = [t.msg_hello, fill(t.msg_kind, ...), ..., t.msg_start, t.msg_file].join('\n');
const href = whatsappUrl + encodeURIComponent(msg);  // '\n' сам станет %0A, иврит и 📎 — правильными кодами
```

Правило на будущее: **в текстах не писать `%0a`, `%20` и т. п. руками.** Кодирует только `encodeURIComponent`
(в JS) или `Uri.EscapeDataString` (в C#).

В иврите число с ₪ обёрнуто в LRM (невидимый символ «слева направо»), иначе «240 ₪» в тексте справа налево
может стать «₪ 240». Символ задаётся в начале страницы (`lrm`), в русском он пустой.

**Проверка.** Нажать «Заказать в WhatsApp» → текст совпадает с ТЗ §5 на обоих языках, есть «Начальный номер: ».

## В2. «4 Книжек» в сводке — склонение

**Было.** `число + "Книжек, 50 комплектов в книжке"`.

**Стало.** Склонять в коде вообще не нужно: количеств в таблице всего шесть (1, 2, 4, 5, 10, 20),
поэтому в resx лежит готовый текст на каждое:

| ключ | ru | he |
|---|---|---|
| `books_1` | 1 книжка | פנקס אחד |
| `books_2` | 2 книжки | 2 פנקסים |
| `books_4` | 4 книжки | 4 פנקסים |
| `books_5` | 5 книжек | 5 פנקסים |
| `books_10` | 10 книжек | 10 פנקסים |
| `books_20` | 20 книжек | 20 פנקסים |

Строка таблицы получает его в атрибут: `<tr data-qty="4" data-books="@L["books_4"]">`.
Скрипт берёт `tr.dataset.books` и подставляет в `qty_line` («{0} по 50 комплектов» / «{0}, 50 סטים בכל פנקס»).
Если добавится новое количество — добавить строку в таблицу и ключ `books_N` в оба resx.

Строка «Ваш заказ» строится по шаблону `summary_line` из resx, потому что порядок слов в иврите другой
(формат владельца 15.11):

| | ru | he |
|---|---|---|
| `summary_a5` | `A5 · {copies} · {qty} по 50 комплектов` | `{qty} בגודל אי5, {copies}, 50 סטים בפנקס` |
| `summary_six` | `Шестёрки · {copies} · {qty} по 50 комплектов` | `{n} שישיות פנקסים בגודל א4, {copies}, 50 סטים בפנקס` |
| `sum_copies_3` / `sum_copies_2` | 3 листа / 2 листа | מקור + 2 עותקים / מקור + עותק |

`{qty}` — это `books_N`. Скрипт просто делает три `.replace(...)`, склеивать куски в коде не нужно.

**Проверка.** ru: «A5 · 3 листа · 4 книжки по 50 комплектов», шестёрки 10 → «10 книжек».
he: «4 פנקסים בגודל אי5, מקור + 2 עותקים, 50 סטים בפנקס», 1 книжка → «פנקס אחד בגודל אי5, …».

## В3 + М1 + М2. Иврит в aria-label на /ru, заголовок столбца, имена атрибутов

`aria-label` кнопок собран из ресурсов: `aria-label="@L["books_1"] · 3 @L["copies"] · 90 ₪"`.
На /ru скринридер читает «1 книжка · 3 листа · 90 ₪», на иврите «פנקס אחד · 3 עותקים · 90 ₪».
Первый столбец — ключ `col_qty` («Книжек» / «פנקסים»).
Атрибуты как в макете: `data-kind-name`, `data-summary`, `data-error` (вместо `pk-kind-name`, `pk-sum-*`).
«A5» в разметке — из ресурса `kind_a5`.

## Б5. Нижняя панель вела на наклейки

**Было.** `_BottomBar.cshtml` всегда показывал «Рассчитать цену наклеек».

**Стало.** Страница выбирает вид панели одной строкой в своём `.cshtml`:

```cshtml
ViewData["BottomBar"] = "order";   // в Pinkasim.cshtml
```

`_BottomBar.cshtml` читает `ViewData["BottomBar"]`. Если там `"order"`, показывает «Итого — ₪ · Заказать →»
(разметка из макета: `data-bar-total`, `data-bar-ok`). Иначе — прежнюю кнопку наклеек, другие страницы не меняются.
Итог и ссылку в панели заполняет скрипт страницы: та же ссылка, что у большой кнопки.

Почему не `@model` в partial: если модель `null`, ASP.NET передаёт в partial модель страницы,
и `@model string` падает с ошибкой типа. `ViewData` общий у страницы и partial-ов, так проще.

Ещё в `layout.css` добавлен `scroll-padding-bottom` на высоту панели: при переходе по Tab поле не прячется под панелью.

**Проверка.** Телефон 390 px → внизу «Итого 240 ₪ · Заказать →», ссылка та же, что у кнопки WhatsApp. На /stickers — как раньше.

## В1. «Назад» не возвращал выбор

Выбор `{kind, copies, q}` сохраняется в `sessionStorage` при каждом изменении (`save()`), при загрузке читается
обратно (`restore()`). Событие `pageshow` с `e.persisted` ловит случай, когда браузер достаёт страницу из кэша
по «Назад». Перед использованием проверяем, что такая кнопка есть в таблице (`valid`), иначе остаётся выбор по умолчанию.
Обращения к `sessionStorage` в `try/catch`: в приватном режиме он может бросить ошибку.

Почему не `window.PRINTABC.store` из `main.js`: `main.js` подключён с `defer` и выполняется позже
inline-скрипта, поэтому в момент запуска скрипта страницы его ещё нет.

**Проверка.** Шестёрки · 2 листа · 10 → уйти на главную → «Назад» → снова шестёрки · 2 · 10, 496 ₪.
